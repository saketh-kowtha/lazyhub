Configuration

lazyhub works with no config. Everything here is optional.

The file

Configuration is TOML at ~/.config/lazyhub/lazyhub.toml. The file is sparse: it holds only what you chose, and first run writes a comment header, never a copy of the defaults, so upgrades can change default keys and actions. Changes apply on the next launch. Invalid or unknown values are dropped with a warning (see lazyhub doctor) and the defaults fill in; a broken file never stops lazyhub from starting.

$ mkdir -p ~/.config/lazyhub && $EDITOR ~/.config/lazyhub/lazyhub.toml
[theme]
name = "catppuccin-mocha"

[defaults]
repo = "owner/name"

[app]
active_panes = ["focus", "prs", "issues"]
default_pane = "focus"

[state]
smartEnter = true     # Enter on a PR row jumps to the failing log, Files changed or conflicts

The [state] table is owned by lazyhub, which may rewrite it at the end of the file when it remembers a choice (for example a PR filter per repository). Keep hand-written notes elsewhere.

Which repository opens

  1. --repo owner/name (this launch only, never saved)
  2. The repository picked in a first-run flow for this launch
  3. The repository detected from the current directory (remote URL or gh repo view)
  4. [defaults].repo, with [defaults].repo_host the host it was saved under; ignored when GH_HOST differs
  5. The interactive picker

Review queue scopes

The review queue (g q) starts on the repository you launched in, from the current directory or --repo. A repository that only came from [defaults].repo, the picker or a owner/repo#123 reference does not narrow it. Without a launch repository it opens on the scope you used last, else your whole account. s cycles: this repository, the account, its organisation and each one below, then each repository set.

[queue]
orgs = ["acme"]

[queue.sets]
work = ["acme/api", "acme/web"]   # up to 20 owner/name entries per set

Set names are 1 to 32 letters, digits, spaces, ., _ or -. Invalid entries are dropped with a warning that lazyhub doctor shows. Queries only ever run against the host gh uses for this launch.

Themes and terminals

The default theme uses only your terminal's 16 ANSI colours, so it follows your terminal scheme. Set [theme].name to one of: terminal, lazyhub-dark, lazyhub-light, github-dark, github-light, catppuccin-mocha, catppuccin-latte, tokyo-night, ansi-16, aurora-dark, aurora-light. Individual tokens go in [theme.overrides], for example "accent.primary" = "#ff7eb6".

  • [ui].icons is auto, unicode or ascii. Auto picks ASCII on TERM=linux or dumb, non-UTF-8 locales and legacy Windows consoles.
  • [ui].no_color = true or a non-empty NO_COLOR drops colour but keeps bold and inverse. FORCE_COLOR and --no-color are honoured, and colour depth follows COLORTERM and TERM.
  • [ui].show_hints = false hides the footer key hints.

Environment variables

VariableEffect
GH_HOSTThe GitHub host, for Enterprise Server. Read by gh and lazyhub.
GH_TOKENA token for gh, for scripts and CI.
NO_COLORSame as [ui].no_color = true when non-empty.
LAZYHUB_GH_CONCURRENCYPositive integer, default 4: how many gh processes run at once. Extra calls queue in order. Not a TOML key.
LAZYHUB_PERFSet to 1 to record timings to a local file for lazyhub perf report. Nothing is sent anywhere.

Keys and actions

Key bindings live in [actions.*] (keys plus label and description) and [keymaps.*]. The shipped defaults are on the keybindings page. A binding that matches a value lazyhub once shipped is treated as an old frozen copy and ignored so upgrades can change defaults; actions you define yourself are kept.

The [ipc].allow_writes setting (default false) lets editor integrations reply to and resolve review threads; a remote config_url can never set it.
