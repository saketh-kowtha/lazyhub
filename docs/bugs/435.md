# Broken lazyhub.toml: saving state threw inside key handlers and dropped [state] keys (#435)

- **Area:** config writer
- **Symptom:** With a TOML syntax error in `lazyhub.toml`, pressing `s` (PR scope) crashed the app, and persisting state deleted every other `[state]` key. Nothing told the user the file failed to parse.
- **Root cause:** `writeConfig()` re-parsed its output after writing and threw; `readState()` swallowed the same parse error and returned `{}`, so `[state]` was rebuilt from the patch alone. Callers (`saveState`, `saveConfig`, `saveDefaultRepo`) did not guard.
- **Fix:** `writeConfig()` parses the existing file first and refuses to write when it is invalid (error says the file is not valid TOML and nothing was written), and validates the new text before it reaches disk. `writeState`, `saveConfig` and `saveDefaultRepo` catch, log, and call `reportConfigWriteFailure()`; the app registers `setConfigWriteNotifier` and shows an error toast (failures before the UI mounts are queued). The file is left byte-for-byte untouched, so other `[state]` keys survive.
- **Regression test:** `src/config/writer.test.js` › "writing into a syntactically broken lazyhub.toml (#435)" (does not throw; file untouched; notice surfaced; writeConfig refuses; other state keys preserved).
- **Follow-up (review):** `migrateStateJsonToToml()` returns `{ migrated: false, reason: 'invalid-toml' }` for an unparsable config and leaves `state.json` in place, so startup cannot crash; `ConfigProvider.write` reports failures through `reportConfigWriteFailure`; the pre-UI notice queue de-duplicates and keeps at most 5. Tests: `src/config/migrate.test.js`, `src/config/provider-write.test.jsx`, `src/config.save-failure.test.js`, `src/config/writer.test.js`.
