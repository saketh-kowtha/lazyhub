# PR write actions showed no pending state and allowed double submit (#453)

- **Symptom:** after confirming merge, close, approve, request changes, auto-merge, label/assignee/reviewer edits or a comment reply, the dialog closed and nothing showed for 1-3 s; the same action could be reopened and submitted again meanwhile. PR detail merge and close printed no status at all.
- **Root cause:** each handler closed its dialog and awaited the call with no busy flag and no pending message.
- **Fix:** small shared hook `src/hooks/usePendingWrite.js`: `run(label, fn)` announces "label..." (sticky status), ignores further runs until `fn` settles, and releases on success or failure. Wired into PR list dialogs, PR detail (merge, close, draft, base, approve, request changes, auto-merge, check re-run, label/assignee/reviewer pickers) and PR comments (reply, edit, delete, resolve). The pickers also show an "Updating" state and submit once. PR detail merge/close now report success. Regression tests: `src/hooks/usePendingWrite.test.jsx`, `src/keystroke-budgets.e2e.test.jsx`, `src/features/prs/list-dialogs.test.jsx`.
- **Remaining surfaces (second pass):** diff view merge/admin merge/approve/request changes (`prs/diff/state.js`), Actions re-run/cancel, Branches checkout/push/delete/new branch, Issues close/create (guard lives in `issues/list.jsx` because the dialogs unmount on close) and issue reply, and the conflict view stage/unstage/setup/commit+push/abort (`prs/ConflictView.jsx`). All use `usePendingWrite`: sticky "label..." status, a repeat submit announces "still in progress" and never runs, success handlers (`onBack`, refetch, success message) run only when the write actually ran. The full `useMutation` (R8) is out of scope.
- **Tests:** `diff/state.test.jsx`, `actions/actions-pending.test.jsx`, `branches/index.test.jsx`, `issues/issues.test.jsx`, `prs/ConflictView.pending.test.jsx`.
- **Status:** all known write surfaces covered.
- **Follow-up (review):** an ignored run now announces "<label> still in progress" instead of dropping the action silently. Esc on the picker's "Updating" shell no longer lets the late completion close a dialog opened afterwards. PR comment pending status stays until the write settles: one flash timer, and pending messages are sticky. A refetch problem after a successful detail merge no longer reports "Merge failed". Tests: `usePendingWrite.test.jsx`, `list-dialogs.test.jsx`, `comments-pending.test.jsx`.
