# Review evidence had no file-level facts, real required checks or stale-head display (#175)

- **Area:** prs
- **Symptom:** the per-PR evidence record (#345) had `required_checks` always `unknown`, no file-level facts, and a failed side read would have thrown away the whole record. Nothing in the TUI could show it.
- **Root cause:** the data layer stopped at the single GraphQL record; there was no read for files or `isRequired`, no comparison of the inspected head with the current one, and no view.
- **Fix:** `src/executor/evidence-detail.js` (stable API in its header): `loadEvidenceDetail` runs three independent reads (record, files by cursor to a 300-file ceiling with total and `truncated`, required checks from GitHub's per-PR `isRequired`). Files and required checks degrade to an explicit `unknown` plus the reason; a head that moves between file pages fails the files read instead of mixing two revisions. `compareHead` marks the inspected revision current, stale or unknown. Pure `evidenceRows` builds the display model (every GitHub string cleaned, author prose last and flagged untrusted). `Part of #175`; branch-protection admin read, persisted cache and the #295 journey test are not in this slice.
- **Regression test:** `src/executor/evidence-detail.test.js`, `src/features/prs/EvidenceView.test.jsx`, `src/render-checks/terminal-text.test.jsx` > review evidence view (the canary test caught unsanitized enum and error-part strings before they shipped).
- **Sibling sweep:** the queue (#177) and detail share `evidence.js`; no change there.
