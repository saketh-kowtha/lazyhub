# Branches pane fired a second heavy PR query with nested check contexts (#456)

- **Area:** branches
- **Symptom:** opening the Branches pane ran the full PR-list GraphQL query (labels, reviewers, 50 check contexts per PR, bodies, assignees; up to 100 PRs) just to put a "PR" marker next to branch names. It capped at 100 PRs, so branches with an open PR past the first 100 had no marker.
- **Root cause:** `src/features/branches/index.jsx` called `useGh(listPRs, [repo, { state: 'open', limit: 100 }])` and scanned the result with `.some()` per visible row.
- **Fix:** new `listOpenPRBranches(repo)` in `src/executor/branches.js`: a GraphQL query for `pullRequests(states: OPEN) { nodes { headRefName } }` only, following the cursor to the last page (each page once, ceiling 50 pages). The pane keeps the names in a `Set`, so each row is an O(1) lookup.
- **Regression test:** `src/executor.test.js` › `listOpenPRBranches()` (query holds no check contexts/body/labels; cursor paging) and `src/features/branches/index.test.jsx` › marks branches with an open PR from a slim head-branch query (the pane no longer calls `listPRs`).
- **Sibling sweep:** other `listPRs` callers are PR/Focus surfaces that show the full rows; none other is used only for a marker.
