# No in-app way to switch repo; `lazyhub --repo` is rejected (#466)

- **Area:** app
- **Symptom:** the only routes to another repository were restarting from another directory or `lazyhub --onboarding`; `lazyhub --repo owner/name` failed with `unknown option: --repo`.
- **Root cause:** `parseCliArgs` knew no `--repo`; the app took its repository once from `GHUI_REPO` at render time and had no switch action.
- **Fix:** `--repo owner/name` (also `--repo=`) is validated with onboarding's `isOwnerName` before anything starts, skips first-run onboarding, wins over the detected and saved repository in `bootstrap()` (`repoOverride`) and is never persisted. The palette has "Switch repository" (`global.switch-repo`), which opens the onboarding picker (`RepoSwitcher`, the same list, search and owner/name lookup, read-only) inside the app. Choosing a repository sets `GHUI_REPO` and remounts `App` through a keyed `AppRoot`, so no pane, selection or request from the old repository survives; Esc/q cancels.
- **Regression test:** `src/cli/usage.test.js` (--repo parsing and errors), `src/bootstrap.repo.test.js` (override precedence, not saved), `src/ui/CommandPalette.test.jsx` (palette action), `src/features/onboarding/Onboarding.test.jsx` (embedded picker), `src/app.e2e.test.jsx` (palette to picker to switch).
- **Sibling sweep:** `watch-only` and `doctor` already take `--repo`. Not done: multi-repo tabs (#317), and `--repo` does not run the `gh repo view` existence lookup the picker runs for typed names (a missing repository surfaces as the usual gh error in the panes).
