# Check runs (30) and notifications (50) were silently capped at one page (#440)

- **Symptom:** a PR with more than 30 check runs showed only the first 30, so failing checks could be hidden. The Notifications pane stopped at 50 with no way to page.
- **Root cause:** `getPRChecks` (`src/executor/actions.js`) and `listNotifications` (`src/executor/notifications.js`) made one `gh api` call with GitHub's default page size and no pagination.
- **Fix:** both page by hand through `runGh` (`per_page` 100 for checks, 50 for notifications, plus `page=N`, stopping on a short page), with no `--paginate`/`--slurp` so there is no gh version floor. A page ceiling (20 pages) bounds the walk. When it is hit, or a later page fails, the pages already fetched are kept and the result carries `truncated` / `error` (`partialError` for notifications): checks get a trailing "checks incomplete" row and the Notifications pane shows a notice. A page-1 failure still falls back to no checks. `all=true` notifications use a 60 s per-call timeout.
- **Regression test:** `src/executor.test.js` ("pagination is never silently capped (#440)").
