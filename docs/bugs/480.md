# Reads had no in-flight dedupe or cancellation (#480, R2)

- **Area:** app (data layer)
- **Symptom:** two panes asking for the same data made two `gh` calls, and a request for a key the user had already left kept running and could be cached. Paged lists had no shared way to append a page without refetching earlier ones.
- **Root cause:** `useGh` owned its fetch, cache and token inside one hook; nothing was shared between hook instances and the key was `fetchFn.name` plus JSON of the deps.
- **Fix:** `src/data/queryClient.js` holds the structured-key cache (byte-budgeted LRU, 64 MB), the in-flight map (identical keys share one promise, a forced refresh starts a new one, a fetch is aborted once every caller released it), `useQuery` (request token, synchronous seed, stale-while-revalidate, `isStale`) and `useInfiniteQuery` (pages by cursor, never refetches earlier pages, `r` refreshes page 1 only, reports `loaded/total/hasMore/capped`). `useGh` is now a shim over `useQuery` with the same signature; the disk cache, `scopedCacheKey` and health reporting are unchanged.
- **Regression test:** `src/data/queryClient.test.jsx` (dedupe, stale drop, abort, sync seed, SWR, paging); the existing `src/hooks/useGh.test.jsx` (#434, #454, #455, #457, #520, #564) passes unchanged.
- **Sibling sweep:** all `useGh` call sites share the hook, so they move together. Invalidation from writes and list-to-detail seeding are R3; no pane was migrated.
