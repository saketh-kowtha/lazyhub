# Claims check: PR description claims were never compared with the diff (#361)

- **Area:** prs
- **Symptom:** "Fixes #88", "adds tests" or "no breaking changes" in a PR description had to be checked by hand.
- **Root cause:** nothing extracted claims from the title and description or compared them with the changed files.
- **Fix (first slice, #574):** `src/features/prs/claims.js` (pure extractor and verifiers), `src/executor/claims.js` (read-only data), `src/features/prs/ClaimsView.jsx` (PR detail key `V`). Each claim is verified, contradicted or unverifiable with file and line evidence. The PR text is untrusted (THREAT_MODEL T3, T4, T20): cleaned with `sanitizeBlock`, only matched by linear patterns, never executed.
- **Fix (second slice):**
  - Optional AI pass (`A` in the claims view, the `diff.ai-review` binding): `src/ai/claims.js` (prompt and strict parser) and `getAIClaims()` in `src/ai/index.js` (provider selection, `logAiUsage`). Only the visible prose is sent, framed between per-call markers the text cannot forge. The model only proposes claims; each must quote the visible text, keeps the description's own words, is marked AI and is checked by the same verifiers. Off when AI review is disabled in Settings; fails closed with no provider.
  - Capped (3000-file) or empty file lists no longer contradict ("no test file changed") or verify ("all files are under X", "only tests and docs changed") by absence; those are unverifiable now.
  - Markdown and wording tricks: struck-through text, HTML tags, closing keywords inside inline code, negated phrases ("adds no tests", "not backwards compatible"), and a longer code fence closed early by a shorter one are no longer read as claims. HTML comments keep their line breaks, so later claims report the right line. A trailing full stop is not part of an "only touches" path.
  - Huge titles and bodies are cut before cleaning, and the notice gives the real length.
  - `checkClaims()` and `claimsReport()` (JSON-ready, every string cleaned) for a future CLI or MCP surface; `claimLabel()` moved out of the view.
- **Regression test:** `src/features/prs/claims.test.js` (fixture matrix per claim type, capped lists), `claims.adversarial.test.js` (escapes, markdown tricks, huge and pathological input), `claims.ai.test.js` (anchoring, merge, report), `src/ai/claims.test.js` (prompt framing, parser, call and usage log), `ClaimsView.test.jsx`, the claims row in `src/render-checks/terminal-text.test.jsx`, and the PTY flow `test/pty/claims.js` (fixture PR, every status, AI pass fails closed offline, hostile text).
- **Sibling sweep:** issue detail has no equivalent description claims; not applicable.
