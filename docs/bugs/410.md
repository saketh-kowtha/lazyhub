# Issue label/assignee dialogs swallow API errors (#410)

- **Area:** issues
- **Symptom:** A failed add/remove of labels or assignees on an issue closed the dialog with no error shown.
- **Root cause:** `IssueLabelDialog` and `IssueAssigneeDialog` in `src/features/issues/dialogs.jsx` wrapped the mutations in an empty `catch`.
- **Fix:** Both dialogs take an `onError` prop. The issue list wires it to a persistent `showStatus(..., true)` error line; the issue detail wires it to a red status line shown for 5 seconds. Mirrors #380 for PRs.
- **Regression test:** `src/features/issues/issues.test.jsx` › `shared issue editor contracts` › `shows an error when a {list,detail} {labels,assignees} update fails instead of closing silently` (failed before the fix).
- **Sibling sweep:** PR dialogs were fixed in #380. Other panes (branches, actions, notifications) are owned by other agents and out of scope here.
