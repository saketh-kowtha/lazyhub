# Collision radar: overlapping open PRs and a suggested merge order (#360)

- **Area:** prs
- **Symptom:** (feature, not a bug) there was no way to see which other open PRs touch the same files or lines.
- **Root cause:** n/a. This file records the design limits so they are not rediscovered.
- **Fix:** `K` in PR detail scans open PRs (GraphQL cursor pages of 50, up to 300 PRs, 100 files each plus up to 3 more file pages) and reports PRs that share files, old-side hunk ranges or git's function heading with the current PR; a repo tab shows clusters and a merge order.
- **Limits, all printed in the view (D16):** PRs beyond the scan ceiling, incomplete PR file lists, overlapping PRs past the first 20 that do not get patches (shown as "same file"), truncated patch lists, per-PR fetch errors.
- **Honesty rules:** "likely" only; hunk comparison uses the base-side lines of each patch; the function heading is git's hint, not a parse; renames are found through REST `previous_filename` and reported as "rename involved".
- **Not done:** a "Collisions" section inside the PR detail body (the key opens the full view instead); line-level comparison for pairs that do not include the current PR.
- **Regression test:** `src/features/prs/collisions/engine.test.js`, `src/executor/collisions.test.js`, `src/features/prs/collisions/view.test.jsx`.
- **Sibling sweep:** n/a (new view; no other pane has a collision concept).
