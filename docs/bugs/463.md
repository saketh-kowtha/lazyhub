# Actions log viewer printed raw TABs and control characters (#463)

- **Symptom:** Enter on a run in Actions: the box border broke on the first line (`build<TAB>Set up job<TAB>2026-01-01T...`), and the title was a bare "Log Viewer".
- **Root cause:** the Actions line mapper only stripped CSI `...m` and its timestamp trim was anchored at `^`, so it never matched gh's `job<TAB>step<TAB>timestamp` lines. `LogViewer` drew whatever it was given, so TAB, CR, BEL and NUL reached the terminal.
- **Fix:** `expandTabs` moved to `src/utils.js` (still re-exported from `src/features/prs/diff/highlight.js`). New `cleanLogLine()` in `src/utils.js` = `sanitize(expandTabs(line))` plus dropping other control characters; `LogViewer` runs every line (and its title) through it, which also covers the PR checks log view. New `toLogLines()` (`src/features/actions/log-lines.js`) drops the job/step columns, trims the timestamp and keeps `##[group]` headers. The viewer title is now `workflow · branch · conclusion`.
- **Regression tests:** `src/components/dialogs/LogViewer.test.jsx`, `src/features/actions/log-lines.test.js`.
- **Left for #463 (needs a recorded design decision):** wiring the #420 failed-log excerpt (`getFailedLog` + `extractExcerpt`) into the UI. #420 lists it as step 4 ("TUI view, `f` key, help and PTY flow, needs Protocol B mockups first") and no mockup exists. Also not done: the single-footer wording (Esc cancel / Ctrl+R re-run vs the box hints) and the swallowed `.catch(() => {})` on Enter for a failed PR check, which live in `src/features/prs/**`.
