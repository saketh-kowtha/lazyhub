# Actions log viewer footer disagrees with the box; failed check opens are swallowed (#463)

- **Area:** actions | prs
- **Symptom:** #549 fixed the raw TABs and the title. Left: the Actions footer under the log viewer said `Esc cancel` and `Ctrl+R re-run` while the box said `[Esc] close` and has no re-run; Enter on a PR check with no annotations (or no id) opened the browser with the result thrown away, so a missing opener looked like a dead key.
- **Root cause:** `DIALOG_KEYS.logs` listed `workflow.rerun` and `dialog.cancel` ("cancel"); the viewer's own footer was a hand-written string. `openCheckInBrowser` ignored the boolean `openUrl()` returns.
- **Fix:** the footer lists scroll, top/bottom, filter and `close`, from the registry, in both places. `openCheckInBrowser` reports a failed open (and the no-annotations fallback) in the PR detail status line.
- **Regression test:** `src/keys.e2e.test.jsx` > "Enter on a check with no annotations reports a failed browser open"; `src/config/key-ownership.test.js` > "log viewer footer".
- **Rest (batch C):** the #420 failed-log excerpt (`getFailedLog` + `extractExcerpt`) is wired into the UI. Decision recorded: in the log viewer a failed job opens on a "Failure excerpt" block (kind, job, step, the failing lines, the file locations; already redacted and capped, and drawn as untrusted log text), and `f` switches between the excerpt and the full log. In the Actions pane a failed run (conclusion failure or timed out) loads the excerpt next to the full log (`failed-logs` dialog); Enter on a failed PR check does the same for its job (`getFailedLog` by job id), with the check's annotations first in the full view. A state other than ok (expired, too large, rate limit, empty) is shown as that state, and a failed check whose log is unavailable falls back to the previous annotations or browser behaviour. Other runs and checks are unchanged.
- **Keys:** new registry action `log.excerpt` (`f`). To free `f`, `log.filter` moved to `/` (the search key everywhere else); `legacy-defaults.js` was regenerated so an older frozen config keeps working. The footer for a failed run lists `f excerpt` (`DIALOG_KEYS.failedLogs`); plain logs keep the old footer, so no hint lacks a handler.
- **Tests (batch C):** `src/components/dialogs/LogViewer.excerpt.test.jsx`, `src/keys.e2e.test.jsx` > "Enter on a failed check opens its failure excerpt", the Actions case in `src/pane-flows.e2e.test.jsx`, and the `runFailedLogFlow` PTY step (real stdin: PR detail, `c`, Enter, `f`, `f`, Esc).
- **Left:** nothing from the issue.
- **Sibling sweep:** the other `openUrl` callers in PR detail (`o`) already surface their failures through the same status line.
