# Actions log viewer printed raw TABs and control characters (#463)

- **Symptom:** Enter on a run in Actions: the box border broke on the first line (`build<TAB>Set up job<TAB>2026-01-01T...`), and the title was a bare "Log Viewer".
- **Root cause:** the Actions line mapper only stripped CSI `...m` and its timestamp trim was anchored at `^`, so it never matched gh's `job<TAB>step<TAB>timestamp` lines. `LogViewer` drew whatever it was given, so TAB, CR, BEL and NUL reached the terminal.
- **Fix:** `expandTabs` moved to `src/utils.js` (still re-exported from `src/features/prs/diff/highlight.js`). New `cleanLogLine()` in `src/utils.js` = strip ANSI, keep text after the last CR, `expandTabs`, then drop C0/C1/DEL and zero-width/bidi control characters. Log text is raw, not HTML; do not entity-decode it, so it never calls `sanitize`; `LogViewer` runs every line (and its title) through it, which also covers the PR checks log view. New `toLogLines()` (`src/features/actions/log-lines.js`) drops the job/step columns, trims the timestamp (only when the third field is a timestamp) and keeps `##[group]` headers. The viewer title is `workflow · branch · conclusion`, skipping empty parts (`logTitle()`, names go through `sanitize`). The PR checks log path shares the viewer and is not decoded again.
- **Regression tests:** `src/components/dialogs/LogViewer.test.jsx`, `src/features/actions/log-lines.test.js`.
