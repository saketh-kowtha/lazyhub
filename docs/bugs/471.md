# Branches pane ran git in the launch directory, not the viewed repo (#471)

- **Symptom:** viewing repo B (default_repo, onboarding choice, non-repo cwd) while launched in directory A: Enter (checkout), `n` (new branch), `p` (push) and the current-branch marker all acted on A.
- **Root cause:** `BranchList` listed branches for `repo` via gh but ran every local command with `cwd: process.cwd()` without checking that directory is a clone of `repo`.
- **Fix:** `findLocalCheckout(repo)` (`src/executor/branches.js`) returns the launch directory only when one of its remotes is `repo`. The pane runs local commands in that directory only; otherwise checkout/new/push are disabled with "No local checkout of <repo> here; run lazyhub inside a clone to use local git actions" and the current-branch marker is hidden. Executor helpers used by the PR flows are unchanged.
- **Regression test:** `src/features/branches/index.test.jsx` (child_process/execa mocked), `src/executor/branches.checkout.test.js`.
- **Follow-up (review):** `remoteMatchesRepo` now compares hosts: the repo's own host, else GH_HOST, else github.com. A github.com clone no longer counts as the checkout of a GHES repo. `findLocalCheckout` returns `{ dir, remote }` and is memoized per (cwd, host, repo). Push uses the matching remote instead of a hardcoded `origin`. For a non-origin remote, checkout fetches and tracks the branch from that remote. Left for #479: `getUnpushedCommits`, `getCurrentBranch`, `pushBranch` in `executor/branches.js`, the `executor/misc.js` git helpers, `ConflictView.jsx` and `useNewPRForm.js` still run git in `process.cwd()` without a repo check. Tests: `src/executor/branches.checkout.test.js`, `src/features/branches/index.test.jsx`.
