# R4: diff-first open, prefetch on cursor rest (#482, closes #451 and #454 with #509)

- **Area:** prs/diff
- **Symptom:** `d` waited on several gh calls (#451); the loader and error view were bare (#454).
- **Root cause:** the diff open fired stats, full PR, diff and threads together on a capped FIFO gh queue, and nothing warmed the diff before `d`.
- **State already on main (#509, #454 work):** `usePRDiffFiles` requests only the file list first (no patch text, no large-diff gate that can replace a rendered diff), patches load per file around the cursor, `DiffSkeleton` and `FailureNotice` are used, `getPR`, `getRepoInfo` and comments wait for `diffReady`. `load-order.test.jsx` pins this.
- **Fix in this PR:** `prefetchPRDiff` / `usePrefetchPRDiff` (`src/features/prs/diff/prefetch.js`) fetch page 1 of the file list into the entry `useGh` reads (same key, same disk-cache key), so `d` finds it fresh or joins the in-flight request. Triggers: PR list cursor resting 400 ms (not while a dialog is open) and PR detail open. `runGh` gained `priority: 'low'`: low calls queue behind normal ones and leave one slot free, so a user call is never delayed by a prefetch (`core.concurrency.test.js`).
- **D16:** prefetch only warms the first page; the open path still pages the whole list by cursor and nothing is truncated.
- **Not done:** the first file's patch is not prefetched (it is not in the query cache; it would need its own entry).
- **Regression test:** `src/features/prs/diff/prefetch.test.jsx`, `src/executor/core.concurrency.test.js`.
- **Sibling sweep:** `listPRFilesPage` already in `src/paging-audit.test.js`; no new fixed-size gh call.
