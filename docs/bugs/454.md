# Diff loader is a bare spinner and cached panes flash a loading frame (#454)

- **Area:** prs (diff), app (hooks)
- **Symptom:** `d` showed a one-line "Loading diff" spinner with no header/footer, and any revisit of a cached pane rendered one loading frame before the cached data.
- **Root cause:** `useGh` initialised `loading=true, data=null` and applied a cache hit only inside an effect; the diff view had a bare Spinner branch.
- **Fix:** `useGh` seeds data/loading/isStale synchronously from the memory cache (then disk cache) and treats an expired memory entry as stale-while-revalidate instead of a loading state. New `DiffSkeleton` (header + bars + footer keys) replaces the spinner, only while there is no diff text yet; the diff error screen now uses `FailureNotice`. Comments and issue detail error screens (`FailureNotice`) and stale indicators in detail are left for #482.
- **Regression test:** `src/hooks/useGh.test.jsx` › "renders cached data on the very first frame with no loading frame"; `src/features/prs/diff/load-order.test.jsx` › "shows a skeleton with header on the first frame, not a bare spinner", "renders a cached diff immediately with no loading frame" (failed before the fix).
- **Sibling sweep:** the `useGh` seed applies to all call sites.
