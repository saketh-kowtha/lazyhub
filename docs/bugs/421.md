# PR list cursor not clamped when the list shrinks (#421)

- **Area:** prs
- **Symptom:** After a refetch returned fewer PRs (merging or closing the last row), the cursor pointed past the end: no row was selected and Enter and the actions did nothing. Same in PR comments (filter cycle, deleted comment) and Logs (search, level filter).
- **Root cause:** `cursor`/`scrollOffset` were only changed by key handlers and never re-clamped when the item count shrank. Comments and Logs could also set cursor to -1 on an empty list.
- **Fix:** Clamp effect keyed on the item count in `src/features/prs/list.jsx`, `src/features/prs/comments.jsx` and `src/features/logs/index.jsx` (mirrors #379/#409); empty-list guards on cursor down/bottom.
- **Regression test:** `src/features/prs/list-cursor.test.jsx` › keeps a valid selection when a refetch returns fewer PRs; `src/features/prs/comments-cursor.test.jsx` › keeps a valid selection when the filter hides the selected comment; `src/features/logs/index.test.jsx` › keeps a valid selection when a search shrinks the list below the cursor (all failed before the fix).
- **Sibling sweep:** Issues (#379), Actions and Notifications (#409) already fixed; Branches owned by another agent; Focus/custom tabs clamp at read time (`cursorOf`, `TabPane`), no gap; Settings lists are fixed-size and wrap.
