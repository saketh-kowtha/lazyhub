# Opening a PR diff fires five gh calls and waits on the slowest (#451)

- **Area:** prs (diff)
- **Symptom:** `d` took 3-4 s before content appeared.
- **Root cause:** `useDiffState` started `getPRDiffStats`, full `getPR`, `pr diff`, comments and `getRepoInfo` together; with the gh concurrency cap of 4, `pr diff` could queue behind them. The large-diff gate also depended on the separate stats call.
- **Fix:** `pr diff` is requested first and alone. Secondary calls (`getPR` for `headRefOid`, `getRepoInfo`, comments) use the new additive `useGh` option `enabled` and start only after the diff has landed. The stats call is gone: the large-diff gate counts +/- lines from the diff text, so it is decided in the same frame the diff arrives, and a gated diff is not parsed. Partially addresses #482 (no prefetch on cursor rest).
- **Regression test:** `src/features/prs/diff/load-order.test.jsx` › "requests only the diff first, renders it on arrival, then loads secondary data", "gates a large diff from the diff text itself, in the frame it arrives" (first failed before the fix).
- **Sibling sweep:** PR comments and issue detail are separate surfaces, left unchanged.
