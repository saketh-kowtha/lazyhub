# Upgrades silently break keys: first launch froze a full copy of the defaults (#475)

- **Area:** config, keymaps
- **Symptom:** After an upgrade, label/assignee/reviewer/approve/merge/diff/open keys did nothing in PR detail, and `q`, `?`, `,` and pr-list `r` pointed at action ids that no longer exist.
- **Root cause:** `writeDefaultConfig()` copied the whole bundled `defaultConfig.toml` (every `[actions.*]` and `[keymaps.*]` table) into the user's `lazyhub.toml`. Config merges per key, so the frozen `scope = "pr-list"` overrode the widened `pr-list,pr-detail` shipped by #340, and renamed ids stayed bound to nothing.
- **Fix:** (a) First run writes a comment-only sparse file. (b) `loadConfig()` runs `stripFrozenDefaults()` (`src/config/migrate-frozen.js`, pure and idempotent) before validation: any action field or keymap binding equal to a value ever shipped (`src/config/legacy-defaults.js`) is ignored, as is any binding to an action id that no longer exists. Genuine customisations survive. Unknown ids that were never shipped are reported once through `takeUnknownActionIds()` as a toast in the app plus a `debug.log` line. The file on disk is not rewritten. When a shipped default changes in future, append the old value to `legacy-defaults.js`.
- **Regression test:** `src/config/migrate-frozen.test.js` (frozen fixture `src/config/fixtures/frozen-pre-340.toml`): PR-detail keys `l A R a m d` resolve; stale ids fall back; real override survives; unknown id warns once; first run is sparse.
- **Not covered:** frozen copies of non-action sections (`[layout]`, `[ui]`, labels under `[panes.*]`) are still pinned for existing users.
