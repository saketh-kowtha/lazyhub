# In-memory gh cache was bounded by entry count, not bytes; open diffs held ~3x (#457)

- **Symptom:** a long session with large diffs/logs could hold well over 1 GB (200 entries x ~7 MB per 100k-line diff); an open diff kept raw text, parsed `files` and spread `flattenFiles` rows at once.
- **Root cause:** `createLruCache(200)` counted entries only, and `flattenFiles` copied every line object (`{ ...line, filename }`).
- **Fix:** `createLruCache` takes `{ maxBytes, sizeOf }` (newest entry always kept); `useGh`'s memory cache is capped at 48 MB by `approxBytes` (cheap, bounded walk) as well as 200 entries, and the disk-cache mirror has its own 16 MB budget; both hold the same payload object, never a second copy. `flattenFiles` now reuses the parsed line objects (stamped with `filename`) instead of copying them, so an open diff is raw text + parsed lines (about 2x) rather than 3x.
- **Regression tests:** `src/cache.test.js` (byte-bounded LRU, `approxBytes`), `src/hooks/useGh.test.jsx` (five 40%-of-budget payloads do not all stay resident), `src/features/prs/diff-parser.test.js` (rows share line objects).
