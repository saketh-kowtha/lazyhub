# useGh re-seed test flaked under coverage; hook returned the previous key's data during the re-seed pass (#548)

- **Symptom:** `useGh seeding (#454) > re-seeds when the key changes...` failed in CI coverage runs with `expected 'a:data=DATA-A loading=false' to be 'b:data=none loading=true'`.
- **Root cause:** two things. (1) Test timing: the test reset its frame log after a fixed `flush(20)`, so under coverage A's trailing `loading=false` render landed after the reset and was read as the first frame of key B. (2) Real, smaller defect found while recording frames in the render body: on a key change the hook called `setData(...)` during render but still returned the old `data`/`loading` values from that pass, so the pass for key B briefly returned key A's data (React discards it, but it was not derived from the new key).
- **Fix:** the seed is derived from `cacheKey` during render and the returned values come from it directly. The test waits with `waitForExpectation` (no sleeps) for A to fully settle, records every render in the body, and asserts the first render for B is `data=none loading=true` with no B render carrying A's data. Verified with repeated `vitest --coverage` runs.
