# Notifications hand-rolled its list, query and write code (#486)

- **Area:** notifications
- **Symptom:** every pane owned its own cursor/scroll/gg/G, loading/empty/failure rendering and write feedback, so fixes such as the shrink clamp (#453, #444) had to be repeated per pane. After a refetch reordered rows the cursor stayed on the same index and pointed at a different thread.
- **Root cause:** no shared primitives; each pane copied the pattern.
- **Fix:** first slice of R8: `useListController` (on `useVirtualList`: gg/G, empty guards, clamp-on-shrink, selection memory by id), `QueryBoundary` (skeleton, empty, `FailureNotice` with retry hint; a failure is never rendered as empty), `useMutation` (pending status, double-submit guard, sticky failure, `invalidates` seam for R3) and `ListRow` (gutter selection glyph). Notifications uses all four and its local cursor, scroll, gg timer, status timer and error/empty code is deleted. Other panes (R9) and the #460 Issues/Actions/PR rows are not migrated yet.
- **Regression test:** `src/hooks/pane-primitives.test.jsx` and `src/features/notifications/notifications.test.jsx` › "keeps the cursor on the same thread when a refetch reorders the list", "shows a failure status and does not refetch when the write fails".
- **Sibling sweep:** the other panes keep their local copies until R9; no behaviour changed there.
