# Failing PR checks had no path from red check to the changed line (#359)

- **Area:** prs
- **Symptom:** finding why CI is red took several clicks and thousands of log lines; Enter on a failed check showed only a log or annotations, with no link to what the PR changed and no base-branch comparison.
- **Root cause:** feature gap. `ci-log.js` (#420) could excerpt a failed log, but nothing matched its file/line references to the PR diff or looked at the base branch.
- **Fix:** `f` in PR detail (and checks mode) opens `WhyRed`: failing check, duration, failing step, redacted excerpt (`ci-log.js`), PR-changed lines matched deterministically by `ci-blame.js` (whole-segment path match, renames, Windows paths, ambiguity returns nothing), and base-branch history from `src/executor/ci-why.js` (at most 3 commits, 1 + N calls). Enter on a failed check already opens the log viewer on the #420 excerpt (#463). Fetches are bounded (5 checks, 6 patches, 10 file pages) and every cap and unknown is shown.
- **Regression test:** `src/features/prs/ci-blame.test.js`, `src/features/prs/why-red.test.js`, `src/executor/ci-why.test.js`, `src/features/prs/WhyRed.test.jsx`, and the failed-log PTY flow in `test/pty/run.js`.
- **Sibling sweep:** the `f` key is free in `pr-detail`/`pr-checks`; in `pr-list` `f` is the filter cycle, so the list does not get this key (open the PR first).
