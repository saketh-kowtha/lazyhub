# An idle TUI kept waking the CPU; a warm re-open of the PR list spent a gh call (#620, #597 WARM-GH:reopen and V6)

- **Area:** app (shell timers, status bar, skeletons, spinners, issue detail, logs, PR list, vitals harness, CI)
- **Symptom:** with nothing changing, the TUI still woke every few seconds: the status bar's 10 s tick (also
  at 80 columns, where the age is never drawn), the issue detail's 30 s poll (also under an overlay or a
  deeper view), the log viewer's 5 s refresh, skeleton pulses and the minute clock of covered views. Going
  back to the PR list fetched the diff of the row the cursor was put back on (`WARM-GH:reopen` = 1).
- **Root cause:**
  - `StatusBar.jsx`, `issues/detail.jsx`, `logs/index.jsx` and `Skeleton.jsx` each ran a plain `setInterval`
    that knew nothing about the covered contract (#597 V3) and there was no idle state at all.
  - `animation.js` and `clock.js` stopped only when nobody subscribed; a covered leaf still subscribed.
  - `features/prs/list.jsx`: restoring the saved cursor counts as the cursor coming to rest, so
    `usePrefetchPRDiff` fetched that row's diff (400 ms after the re-open) when the user had left before it
    had been prefetched.
- **Fix:**
  - `src/shell/activity.js`: the idle detector. Idle after `DEFAULT_IDLE_AFTER_MS` (2 min) without a key
    (`LAZYHUB_IDLE_MS` overrides it; the vitals harness uses 3 s). `useRootInput` (`src/hooks/useSafeInput.js`)
    calls `noteActivity()` on every key. One timeout, armed only while somebody subscribes and the app is
    active; it is not re-armed per key, and none is pending once idle.
  - `useCoveredInterval(fn, ms, tag)` (`src/shell/covered.js`) pauses while covered or idle. On resume a tick
    that came due meanwhile runs at once (no stale data after an idle spell or a long cover); otherwise the rest
    of the period is waited out, so opening and closing an overlay costs no poll. The issue detail poll and the
    log refresh use it.
  - Skeleton pulse: no timer while covered or idle. Animation slot: a covered leaf does not claim; the tick
    stops while idle and restarts on the next key.
  - `src/ui/clock.js` is the one shared clock: one epoch-aligned timer for every period asked for
    (`useClock(ms)`, `useMinuteClock()`), a listener is called only when its own period rolls over, and a
    covered view does not subscribe. The status bar subscribes at 10 s only while its age can be drawn
    (not on a bar narrower than 100 columns, not with `hideAge`).
  - PR list: the row a re-open restores the cursor to is not prefetched until the cursor moves.
  - Vitals: when `LAZYHUB_VITALS=1` the recorder wraps `setTimeout`/`setInterval` and writes a `wake` event
    (code tag, kind, delay; nothing else) per fired callback (`instrumentTimers`, `tagTimer`).
    `idleWakeups()` clusters callbacks < 100 ms apart into one wakeup. The harness adds
    `IDLE-WAKEUPS:covered` (help over the issue detail), `IDLE-WAKEUPS:idle` (issue detail with a 3 s idle
    period), `IDLE-CPU` (reported) and `IDLE-RESUME` (the first key after an idle minute refreshes the overdue
    poll). `EXPECT_FAIL` is empty and CI runs `npm run vitals` in the Performance budget job (V6 gate flip).
- **Timer inventory (non-test src):** recurring: `shell/covered.js` (issue detail poll, log refresh),
  `ui/animation.js`, `components/Skeleton.jsx`, `ui/clock.js` (status bar age, relative times), all gated as
  above; `src/shell/idle.test.jsx` fails on a new `setInterval` outside them. One-shot and self-ending:
  status and toast expiry, chord windows (`useChords`), `gg` window, cursor-rest preview and diff prefetch,
  the skeleton delay and revalidate kick in `data/queryClient.js`, the disk-cache flush (250 ms after a write),
  resize debounce, request timeouts (`config/loader.js`, AI providers), daemon lifecycle probes. None of them
  runs while nothing happens.
- **Measurements (`npm run vitals`, 80x24, fake gh 300 ms/call, macOS):**

  | Metric | main | after |
  |---|---|---|
  | WARM-GH:reopen | 1 call | 0 |
  | IDLE-WAKEUPS:covered (60 s, help over issue detail) | 13 | 0 (+0 clock) |
  | IDLE-WAKEUPS:idle (60 s, issue detail, idle) | 11 | 0 (+0 clock) |
  | IDLE-CPU covered / idle | 0.6 % / 0.6 % | 0.1 % / 0.1 % |
  | IDLE-RESUME (gh calls on the first key) | 0 | 2 (header + page 1) |

  On main the idle wakeups were the status bar's 10 s tick (6/min, nothing drawn at 80 columns), the 30 s
  poll (2/min) with its follow-up revalidation, and the minute clock. Every other vitals metric is unchanged
  and passing (FMF-cold 442 ms, FMF-warm 35 ms, KTF-nav p95 9 ms, KTF-open 7 ms, CLEAR 0, FLASH 0).
- **Regression tests:** `src/shell/idle.test.jsx` (per site: 0 pending fake timers while covered and while
  idle, resume and the due-tick rule, the status bar and minute clock, a whole screen ticking 0 times over an
  idle minute, the `setInterval` audit), `src/features/prs/reopen-prefetch.test.jsx` (fails on main),
  `src/perf/vitals.test.js` (wake events, privacy), `src/perf/vitals-metrics.test.js` (`idleWakeups`).
- **Sibling sweep:** every `setInterval`/`setTimeout` in `src` (inventory above). Not done: terminal focus
  reporting (DEC 1004) as a "hidden" signal; it needs stdin parsing and a startup escape, which belong to the
  stdout/startup lane.
