# Hermetic canary fails when another worktree creates a branch (#546)

- **Area:** ci
- **Symptom:** `random-keys` "left no trace" failed during parallel full runs although the fuzz touched nothing; it passed alone.
- **Root cause:** the canary snapshotted `git branch --list`, which is shared by every worktree of a clone.
- **Fix:** the snapshot now covers only state this worktree owns: `rev-parse HEAD`, `symbolic-ref HEAD` and the per-worktree HEAD reflog (`<git-dir>/logs/HEAD`). The PATH-shim canary is unchanged and stays the primary signal.
- **Regression test:** `src/random-keys.e2e.test.jsx` › "a branch created by ANOTHER worktree does not trip the canary, but a checkout in this one does".
- **Sibling sweep:** no other test snapshots shared refs.
