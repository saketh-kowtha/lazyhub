# Hermetic canary fails when another worktree creates a branch (#546)

- **Area:** ci
- **Symptom:** `random-keys` "left no trace" failed during parallel full runs although the fuzz touched nothing; it passed alone.
- **Root cause:** the canary snapshotted `git branch --list` of the real checkout. Branch refs, tags and their reflogs live in the common git dir shared by every worktree, so any other worktree changing them tripped it. Comparing only HEAD and the per-worktree reflog avoided that but missed `git branch X`, `branch -f`, `tag` and `update-ref`.
- **Fix:** the fuzz runs with `process.cwd()` set to a throwaway git repo created in `os.tmpdir()` (removed afterwards). The canary compares that repo's HEAD, symbolic ref, `for-each-ref` and worktree list, so it is immune to other worktrees and still catches any ref mutation the app makes. The PATH-shim canary is unchanged and stays the primary signal.
- **Regression test:** `src/random-keys.e2e.test.jsx` › "git branch X / branch -f / tag / update-ref / checkout -b run from the fuzz cwd is caught" and "a branch created in a different worktree or clone does not trip the canary".
- **Sibling sweep:** no other test snapshots shared refs.
