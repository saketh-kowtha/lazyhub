# Label, assignee and reviewer pickers: dead while loading, silent on failure, stale selection (#513)

- **Area:** prs | issues
- **Symptom:** earlier PRs (#524, #551) made the pickers closable while loading, retryable on failure and safe against stale selections. Left: the PR pickers capped the collaborator list at the paging ceiling without saying so, and a failed load showed only the generic classification ("Your gh login cannot read this."), not the cause gh gave (for example, listing collaborators needs push access).
- **Root cause:** `PRSelectionDialog` did not use `collaboratorsTruncated()` (the issue dialogs did), and neither dialog rendered the error message under `FailureNotice`.
- **Fix:** PR pickers show `showing first N collaborators` when the list hit the ceiling. Both PR and issue pickers print the first line of gh's message (sanitized, 100 columns) under the failure notice, beside `[r] retry` and `[Esc] close`.
- **Regression test:** `src/features/prs/list-dialogs.test.jsx` > "PR pickers: notices (#513)".
- **Sibling sweep:** issue label/assignee dialogs, PR list and PR detail pickers (they share `PRSelectionDialog`); dead-while-loading and stale-selection behaviour were re-checked against the audit proofs and already pass.
