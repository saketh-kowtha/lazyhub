# Issue label and assignee pickers were dead while loading, silent on failure and stripped unlisted values (#513)

- **Area:** issues
- **Symptom:** the issue label and assignee pickers showed a bare "Loading..." that ignored Esc, showed an empty list when the fetch failed (no reason, no retry), dropped any label or assignee that the fetched list did not contain, and applied add and remove as two separate calls so a failure could leave half the change. Collaborators were read from the first page only.
- **Root cause:** `src/features/issues/dialogs.jsx` rendered `Loading...` with no input handler, ignored `error` from `useGh`, built the checked set only from fetched options, and issued `addLabels`/`removeLabels` (and the assignee pair) sequentially. `listCollaborators` made one unpaged `gh api` call.
- **Fix:** the issue pickers share one `IssueSelectionDialog`, mirroring the PR side: Esc closes while loading, a failure shows `FailureNotice` with `r` to retry, values already on the issue that the list lacks stay checked, and the change is one `editIssueMembers` call (`gh issue edit --add-* --remove-*`) with an "Updating #n" shell and a submit-once guard. `listCollaborators` now follows pages of 100 until a short page (ceiling `COLLAB_MAX_PAGES`, 50 pages), fetching each page once.
- **Regression test:** `src/features/issues/issues.test.jsx` (unlisted label kept, Esc while loading, failure + retry, one edit call), `src/executor.test.js` (`listCollaborators` pages, `editIssueMembers`).
- **Sibling sweep:** PR pickers already fixed (`prs/list-dialogs.jsx`); issue list and issue detail share these dialogs, so both are covered. The PR-side `PickerStatus` is private to `prs/list-dialogs.jsx` (not this lane's file), so the issue side carries its own small copy. Collaborator listing is shared with the PR assignee and reviewer pickers, which now also get every page.
