# #489 R11: machine-checked invariants (first ratchet)

Part of #489. Later steps ratchet again after the other R-PRs land.

## Already in place when this PR started
- `no-empty` as an error (a comment inside the block is the allowed reason), `complexity` (25) and
  `max-lines-per-function` (150) as warnings, and the `--max-warnings 20` budget. The real count is 20,
  so the budget is already exact and was not lowered.
- Source scans in `src/lint-invariants.test.js` for unsanitized GitHub fields in `<Text>` (with an
  allowlist of fields sanitized upstream) and for literal hex colours.

## Added
- `noImplicitAny` for `src/executor/`, `src/config/` and `src/daemon/protocol.js`.
  `tsconfig.strict.json` extends the base config; `scripts/typecheck-strict.mjs` runs it and reports
  only the opted-in paths (tsc follows imports into directories that have not opted in, such as
  `src/cache.js`). `npm run typecheck` runs both. To opt a directory in, add it to the `include` and
  to `STRICT` in the script. `tsconfig.strict-shims.d.ts` declares `react` untyped for this config only.
- Fixes: `{Object}` / `{object}` JSDoc types became `Record<string, any>`, untyped parameters and
  accumulators got explicit `any` annotations. No runtime change.
- A scan for literal named / `rgb()` / `hsl()` colours on `color`, `backgroundColor` and `borderColor`
  props (baseline 0), and a test that the ratchet stays wired into `npm run typecheck`.

## Left for later steps
- Tighten the explicit `any` annotations to real types, and opt in more directories.
- Lower the warning budget as the complexity and function-length warnings are fixed.
