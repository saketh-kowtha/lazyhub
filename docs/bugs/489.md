# The AGENTS.md rules were enforced by review, not by CI (#489, R11)

- **Symptom:** an empty `catch {}`, a GitHub title or branch name drawn without `sanitize()`, and a literal hex colour could all land without any check failing. Part of this was already merged (no spawn in UI code, no static `t` import; `src/lint-invariants.test.js`).
- **Fix (batch C, the cheap machine-checked parts):**
  - ESLint `no-empty` is an error. An empty block is allowed only when it holds a comment that says why (`catch { /* closed stream */ }`). Two bare catches in `src/crash.js` and `src/perf.js` got their reason.
  - `complexity` (25) and `max-lines-per-function` (150, blank lines and comments skipped) are warnings. The budget is `--max-warnings 18` in the `lint` script (18 warnings today, none new); lower it whenever a function is split, never raise it.
  - A source scan in `src/lint-invariants.test.js` fails when a `<Text>` renders a bare `title`, `body`, `login`, branch name, path, summary or commit message without `sanitize()`. It found four real renders, now sanitized: the unpushed-commit messages in the New PR form, `pr.baseRefName` in PR detail and `baseRefName`/`headRefName` in the conflict view, and file-tree names in the diff. Two sites that are sanitized where the row is built are listed with the reason. App-authored text (`err.message`, toasts, the app's own debug log) is out of scope.
  - A source scan fails on a literal hex colour in UI code beyond a recorded baseline (10 white glyph colours in `src/features/prs/diff/render.jsx`); the two literal fallbacks in `AIAssistant.jsx` now use theme tokens.
- **Left (Part of #489):** TypeScript `noImplicitAny` per directory and the typedefs for PR, Issue, Run and Branch; removing `@ts-nocheck` from the remaining files; the coverage floors (remove the `list-view.jsx` exclusion, floors at measured minus 3, per-directory floors for `components/` and `features/`); `knip` stale entries; the ESLint flat-config migration. Also left: the 10 literal colours in the diff renderer, and the `.jsx` files are still not parsed by ESLint, so `no-empty`, `complexity` and the length rule only cover `.js` (the source scans cover both).
- **Regression tests:** `src/lint-invariants.test.js` > "empty blocks need a reason", "warning budget", "GitHub text is sanitized before it is drawn", "colours come from the theme".
