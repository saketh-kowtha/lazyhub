# The "Closed" PR filter spent its page on merged PRs (#425)

- **Symptom:** the closed filter showed a fraction of the page size and never loaded older closed PRs, because GitHub search counts merged PRs as `state:closed`, the list then dropped them client-side, and the "load more" check compared the filtered count with the fetch limit.
- **Root cause:** the closed query did not exclude merged PRs.
- **Fix:** the PR pane was already moved to cursor pages with a server-side `is:closed -is:merged` query by the #554 paging work, so a closed page holds only rows the list shows and `totalCount` is real. This change fixes the remaining callers of the older `listPRs` (custom tabs, MCP `list_prs`, the AI assistant): `state: 'closed'` now sends `is:closed -is:merged`, matching `gh pr list --state closed`.
- **Regression tests:** `src/executor/prs.page.test.js` (pane query, from #554), `src/flows.test.js` and `src/executor.test.js` (legacy `listPRs`).
