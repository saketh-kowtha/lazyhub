# Every write refetched the whole repository (#597, lane V2a)

- **Area:** app (src/data/mutations, `useMutation`, Notifications, Actions, Branches, Issues list)
- **Symptom:** one write made unrelated views reload. Marking a notification read cost 2 gh calls and marked every cached read of every repository stale (the write has no `--repo`, so `runGh` announced `repo: null`); deleting a branch cost 4; closing an issue 3; the row only changed after a refetch.
- **Root cause:** `runGh` calls `notifyWrite(repo)` after every write and the query client invalidated everything under that repo (or everything, for an unattributed write). `useMutation` then ran its own `refetch()` on top. Nothing said which reads a write actually touches, and no cache patch was applied before the server answered.
- **Fix:**
  - `src/data/mutations/core.js`: `defineMutation({ name, run, optimistic, invalidates })` declares a write; `runMutation` applies the optimistic patch with `client.updateQueryData`, runs the write inside `runDeclared`, rolls the patch back on failure (not over a value a refetch stored meanwhile) and invalidates only the declared key prefixes.
  - `src/data/invalidation.js`: `runDeclared` (an `AsyncLocalStorage` scope). `notifyWrite` now reports `declared`; the query client skips its repo-wide invalidation for a declared write. An undeclared write keeps the fallback, is recorded (`undeclaredWrites()`), and logs a warning to the debug log when `NODE_ENV=development` or `LAZYHUB_DEV=1`. `src/executor/core.js` is unchanged.
  - `useMutation(spec, { onSuccess })` accepts a declared spec; the failure line says `(change reverted)` when a patch was undone. A bare function still works and stays undeclared.
  - Declarations: notifications mark read / mark all (row leaves the cached list, no refetch); actions rerun / cancel (row shows queued / cancelling, one run-list read); branches delete (row removed, no refetch), push / checkout / create (local git, no gh); issues close (cached row state, then the one `getIssueRow` read), create, label/assignee edit (`editIssueMembersDeclared`, shared with the detail dialogs).
- **ACT-GH (gh calls per action, fake gh call log), before to after:** mark read 2 to 1; mark all 3 to 1; open notification 2 to 1; re-run: mutation + 1 run-list read (other repos and branches stay fresh); branch delete 4 to 1; issue close 3 to 2 (close + `issue view`).
- **Regression tests:** `src/data/mutations/act-gh.test.jsx` (all 8 fail on main), `src/data/mutations/declared-writes.test.js` (undeclared-write enumeration for the four views, scope, rollback, targeted invalidation).
- **Left for later lanes:** the issue detail view's own writes (comment, edit, reopen) and every PR write stay on the repo-wide fallback until V2b. Closing an issue still drops the row once the re-read says it left the filter (the no-shift "row stays marked" behaviour of table 2.4 is V2b). Creating a local branch no longer refetches the remote branch list (it cannot change it).
