# Focus dashboard was display-only: no cursor, no open, no help (#279)

- **Area:** app (Focus / TOML dashboard tabs)
- **Symptom:** the default Focus pane showed up to eight rows per section but nothing could be selected or opened; footer and `?` help had no Focus keys.
- **Root cause:** `src/features/tabs/pane.jsx` rendered static rows and `TabView` had no key handler and no item-opening callback; `contextScopes()` had no scope for a TOML tab, so footer/help were empty.
- **Fix:** `TabView` owns a section + per-section cursor (j/k, gg/G, `]`/`[`), Enter opens the PR/issue through `goToDetail` (item carries `_kind`; `app-views.jsx` picks the detail component from it), `o` opens the browser, `r` refreshes. The selection is kept in a per-tab store so Esc from detail restores section, row and scroll window. New `tab-list` scope plus `tab.*` registry actions drive the footer and `?` help. Only a loaded, error-free list can be selected. No visual redesign: existing layout plus a `▸` marker, bold row and active border from `useTheme()` tokens.
- **Regression test:** `src/focus-interactive.e2e.test.jsx` (failed before the fix; 6 of 7 cases).
- **Sibling sweep:** every TOML `[[tabs]]` dashboard shares `TabView`, so custom tabs get the same behaviour and help (`contextScopes` resolves tabs from `config.tabs`). Other panes already had cursors/handlers.
