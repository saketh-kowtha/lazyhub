# Default Focus dashboard: actionable, truthful help, fits the screen (#279)

- **Area:** focus (tabs)
- **Symptom:** earlier PRs made the rows selectable and openable with registry-driven footer and help. Left: at small sizes the three sections each kept eight rows, so they overflowed and overlapped (the cursor row could be drawn under the next section's border), and the help text for Focus wrapped past its box.
- **Root cause:** `TabPane` always drew `VISIBLE_ROWS` rows with `flexGrow` boxes and no height budget.
- **Fix:** `TabView` splits the height it is given (`sectionBudget`): equal shares when each section can show a row, otherwise one section at a time with a `section 2/3` marker (`]` / `[` still move between sections). Rows are exact-width single lines, the window follows the cursor inside the budget and ends in `+N more`. The help overlay (see #512) keeps the Focus rows on one line.
- **Regression test:** `src/features/tabs/view.test.js`; the Focus cases of `src/screen-matrix.e2e.test.jsx` at every size; `src/focus-interactive.e2e.test.jsx` still covers navigation, open, return and refresh.
- **Rest (batch C):** the PTY flow now exists (`runFocusReturnFlow` in `test/pty/run.js`): on a real PTY with real stdin it goes Focus -> last PR (`G`) -> detail -> Esc -> `]` `]` -> last issue -> detail -> Esc -> `[` `[`, at 100x40 and 80x24 (three sections stacked) and 60x16 (one section at a time). It asserts the section, the selected row and the scroll window (the first rows stay out of view) after each return. Running it found a real defect: in one-section mode the sections that are not drawn are not mounted, so after coming back from a detail view `cursorOf` clamped the remembered row of an unloaded section to 0 and pressing `k`/`j` then moved from row 0. `cursorOf` (`src/features/tabs/view.jsx`) now keeps the stored row until the section reports its length. The PTY gh stub gained `LAZYHUB_GH_MANY=N` (numbered PRs and issues) and `TerminalScreen.feed` now keeps an escape sequence that a PTY chunk split.
- **Design, recorded:** the one-section-at-a-time mode on small terminals (`section 2/3` marker, `]`/`[` to move) is the shipped design for terminals too short to give three sections a row each. No mockup is needed; the layout can still change under #201.
- **Regression test (batch C):** `src/features/tabs/selection.test.jsx` (failed before the `cursorOf` change), and the three `runFocusReturnFlow` runs in `npm run test:pty`.
- **Left:** nothing from the issue.
- **Sibling sweep:** other TOML dashboards use the same `TabView`/`TabPane`, so they get the same budget.
