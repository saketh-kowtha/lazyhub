# PR conversation comments never shown; review threads silently capped at 100 threads / 50 replies (#507)

- **Area:** prs
- **Symptom:** On a PR with hundreds of conversation comments the comments view listed inline review threads only. More than 100 review threads, or a thread with more than 50 replies, was silently cut off with no notice.
- **Root cause:** `listPRComments` and `getPRReviewComments` (`src/executor/pr-comments.js`) queried `reviewThreads(first: 100) { comments(first: 50) }` without `pageInfo` or cursors, and no code path fetched `pullRequest.comments` (conversation comments).
- **Fix:**
  - `listPRTimelinePage` fetches one cursor page of review threads and/or conversation comments in one request. A thread with more than 50 comments comes back in `partialThreads`; `listPRThreadReplies` loads its next page on demand. Nothing is fetched per thread on first render.
  - The comments view keeps every loaded page in its own state and patches it in place after a reply, edit, delete or resolve, so a write never drops loaded pages; only `r` reloads. Conversation pages load near the end of the conversation block, thread pages near the end of the threads, and the selection is anchored to the highlighted comment so inserted rows never move it to another one. A thread's "N more replies" row loads the rest when the cursor reaches it. The header always says "conversation N of M, threads N of M".
  - A cursor that does not advance is reported as incomplete (no page-count cap, no loop). `listPRComments` (diff, AI tool) returns the first page only and an array property `truncated`; the diff view, `list_pr_comments` and the IPC `review-comments` response surface it. `getPRReviewComments` (IPC) still walks every page and reply page, guarded by the cursor check.
  - Conversation rows are reply-only: the prompt says it posts a new PR comment (prefilled with `@author`), and the edit, delete, resolve and jump hints are hidden.
- **Regression test:** `src/executor.test.js` > `PR timeline paging (#507)`; `src/features/prs/comments-writes.test.jsx` (real `useGh`; writes keep pages, section paging, selection anchor, on-demand replies, incomplete notice, conversation rows); `src/features/prs/comments-paging.test.jsx`; `src/features/prs/diff/state.test.jsx`; `src/ai-assistant.test.js`; `src/ipc.test.js`.
- **Sibling sweep:** `getPRReviewComments` (IPC) had the same cap and is fixed; diff inline threads, the AI tool and IPC all report truncation. Issues pane comments were not touched.
