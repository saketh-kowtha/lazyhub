# PR conversation comments never shown; review threads silently capped at 100 threads / 50 replies (#507)

- **Area:** prs
- **Symptom:** On a PR with hundreds of conversation comments the comments view listed inline review threads only. More than 100 review threads, or a thread with more than 50 replies, was silently cut off with no notice.
- **Root cause:** `listPRComments` and `getPRReviewComments` (`src/executor/pr-comments.js`) queried `reviewThreads(first: 100) { comments(first: 50) }` without `pageInfo` or cursors, and no code path fetched `pullRequest.comments` (conversation comments).
- **Fix:** New `listPRTimelinePage` fetches one cursor page of review threads and/or conversation comments, and completes any thread's replies past 50 by cursor. `listPRComments` (diff, AI tool) and `getPRReviewComments` (IPC) now follow thread cursors to the end. The comments view loads the first page, shows conversation comments before threads, loads the next page when the cursor nears the end of what is loaded, renders only the visible window (`useVirtualList`), and always shows "conversation N of M, threads N of M". `f` gains a `conversation` filter. Conversation comments are reply-only here (reply posts a PR comment); edit/delete/resolve/jump stay review-comment actions.
- **Regression test:** `src/executor.test.js` › `PR timeline paging (#507)` (failed before the fix); `src/features/prs/comments-paging.test.jsx`.
- **Sibling sweep:** `getPRReviewComments` (IPC) had the same cap and is fixed; diff inline threads use `listPRComments`, now complete. Issues pane comments were not touched.
