# #597: whole view reloads on every action (lane V3: overlays as layers, keep-alive navigation)

## Risk 2: does Ink 4 support Box `display="none"`?

Yes. Ink 4.4.1: `node_modules/ink/build/styles.js` maps `display: 'none'` to `Yoga.DISPLAY_NONE`, and
`render-node-to-output.js` returns early for such a node, so it and its subtree write nothing to the output.
The subtree stays mounted (hooks, state, effects live on). Covered layers use it; the fallback ("body null
below the hooks") was not needed. `src/shell/layers.e2e.test.jsx` asserts that a hidden view changing its
own state leaves the screen byte-identical.

## Risk 5: hidden subtrees

A covered view still re-renders when its own state or a subscribed query changes (React cannot be told to skip
that from the shell), but the screen is unchanged, and Ink drops a frame equal to the previous one
(`ink.js`: `output !== this.lastOutput`), so no stdout bytes are written. Chrome (sidebar, status bar and its
10 s clock, footer, toaster) is not rendered at all for a covered layer. Open follow-up for V1/V5: `useQuery`
could read `useCovered()` and defer renders while covered.

## Risk 6: keep-alive memory

At most 3 layers are mounted (the active one plus 2 covered; `MAX_MOUNTED` in `src/shell/navStack.js`). Going
deeper evicts the oldest covered layer to a snapshot in the view-state store (`src/shell/viewState.js`, 20
snapshots, per App instance, plain data: pane, view, item number, the pane's saved state). Rebuilding an
evicted list seeds the App's `paneStateMap` from the snapshot before it mounts. The RSS gate is unchanged.

## What changed

- `renderAppView` now returns `<AppViews>`: layers keyed by view identity (`list:<pane>`, `detail:<kind>:<repo>#n`,
  `diff:...`, ...). Help, palette, AI, repo picker and the too-small message are layers on top; the base
  view under them stays mounted (before: a different tree replaced it, so it remounted, refetched and lost its cursor).
- list -> detail -> diff keeps the last mounted views covered; going back finds the same instance (REMOUNT 0, WARM-GH 0).
  A list pane that is not covered starts a new root; leaving a view for a deeper one pushes, back pops.
- `covered` contract (`src/shell/covered.js`): `useCovered()`, `useCoveredInterval()`. The focus manager
  (`useFocusEntry`) releases claims of a covered view, so it receives no keys. A covered view's `onPaneState` calls
  are kept and replayed when it is uncovered, so it cannot overwrite the footer/count of the view on screen.
- The `_fromQueue` / `_fromEvidence` / `_fromList` back chains are untouched (App's navigation state is not changed).

## Not done here (other lanes' files)

- `src/features/issues/detail.jsx` polls with its own `setInterval`; it must use `useCoveredInterval` (or read
  `useCovered()` in its `pausedRef`) to pause while covered. Only the issue detail polls; lists do not.
- Lists other than the PR list do not persist cursor/scroll across an unmount (`usePaneState` is used by PRList
  only). Kept alive they keep it for free; after eviction (4+ deep) they rebuild at the top until V4a/V5 adopt the store.
