# Selection and PR state are conveyed by colour only (#460)

- **Area:** issues | actions | branches | prs
- **Symptom:** under `NO_COLOR=1` the cursor disappeared on Issues and Actions rows, and merged and closed PRs were not distinguishable from open ones.
- **Root cause:** each pane drew its own row with its own selection marker (`▎`, `▶`, or none). Issues and Actions had since gained `▎`, and the PR badge already used `●` open, `◆` merged, `○` closed, but nothing shared the marker or guarded the state glyphs, so Branches still used `▶` and the rows could drift apart again.
- **Fix:** Issues, Actions, Branches and PR rows are all drawn through `src/ui/ListRow.jsx` (R9, #487), which owns the gutter glyph. Every glyph in use (`▎ ● ◆ ○`) is in the ASCII `GLYPH_MAP` in `src/theme/terminal.js`.
- **Regression test:** `src/ui/list-row-glyph.test.jsx` › "marks the selected issue and PR row, and only that row", "uses a different glyph for open, merged and closed", "every state glyph has an ASCII stand-in". Note: the symptom was already fixed on main before this PR for Issues/Actions/PRs, so these tests guard it rather than going red-to-green; the Branches test in `src/features/branches/index.test.jsx` moved from `▶` to `▎`.
- **Sibling sweep:** Notifications already used `ListRow` (R8). Remaining rows not on `ListRow`: Logs, CustomPane, Focus queue.
