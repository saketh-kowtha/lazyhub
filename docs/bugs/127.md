# PR evidence had no read-only view and no return path (#127)

- **Area:** prs
- **Symptom:** evidence existed only as an executor API; a reviewer could not see sources, freshness or whether the head changed since they started reading.
- **Root cause:** no UI consumed the evidence record.
- **Fix:** `src/features/prs/EvidenceView.jsx`, opened from PR detail with `e` (`pr.evidence`). Read-only (no write verb, no AI), source and read time of the selected row, a loud banner when a refresh finds a different head than the one first read. Return continuity is a seam: the caller passes `returnTo` (`returnTarget({view, position, filter, key})`) and `onReturn`; Esc hands the same target back, so the queue can restore position and filter. Without a target Esc calls `onClose`. `Part of #127`; the queue wiring itself belongs to #177 and the diff-to-evidence back chain is not in this slice.
- **Regression test:** `src/features/prs/EvidenceView.test.jsx`.
- **Sibling sweep:** the claims, why-red and collisions views use the same dialog scope and were not changed.
