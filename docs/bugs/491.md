# Daemon spawned before the first frame; IDE socket had no session token; daemon fallback was silent (#491, part of the R13 step)

- **Symptom:** cold start included the daemon probe and spawn window before anything was drawn; the IDE socket accepted any same-user process without a credential while the daemon required one; when a daemon read failed the app silently went direct to `gh`.
- **Fix:**
  - `bin/lazyhub.js` no longer awaits the daemon. `scheduleDaemon()` (in `src/daemon/lifecycle.js`) runs after `renderApp()` returns, in the background.
  - `src/ipc.js` uses the daemon's session-token model: a per-run secret in `<socket>.token` (0600, removed on exit), protocol version `v` and `auth` required on every request, connections receive pushed events only after an authenticated request, and lines over the daemon's size limit close the connection. The nvim and VS Code clients send both fields.
  - `src/daemon/fallback.js` records "running without the background helper". The status bar shows it when no call is failing; a failed daemon read also pauses daemon use for 30 seconds so a hung helper cannot slow every read.
- **Rest (batch C):**
  - `src/daemon/wire.js` is now the one module for framing (NDJSON lines, the 64 KiB limit, `E_TOO_LARGE` and close), the request envelope (`parseRequest`: JSON object, protocol version, id), denials (`deny`/`send`), secret rotation (`currentSession`) and the secret check (`authorize`). `src/daemon/server.js` and `src/ipc.js` use it and keep only their own message types and policies. Both servers' behaviour is kept: the daemon still answers a malformed line with `E_MALFORMED` and only asks for the secret on control messages; the editor socket still ignores a line that is not a JSON object and still asks for the secret on every request. One failure-path change: the daemon now keeps an expired secret and refuses clients when it cannot write the replacement (the editor socket already did), where before the rotation error escaped its async handler.
  - A PTY timing check (`runColdStartFlow` in `test/pty/run.js`) puts a listener that accepts and never answers at the helper's socket path and measures spawn to first frame with the helper disabled and with the hung one, median of three, and requires that the hung helper was still probed (after the frame). Measured here: 564 ms with no helper, 563 ms with the hung helper (runs 566/564/564 vs 563/562/563). With the launcher temporarily changed to await `ensureDaemon` before rendering, the same check measured 4758 ms and failed.
- **Threat model:** T7 (alternate paths). Mitigation unchanged: same-user 0700 directory and 0600 socket, per-run secret, version and size checks on both sockets, writes off by default. Residual risk unchanged: a same-user process that can read the token file is trusted.
- **Left:** nothing from the issue.
- **Regression tests:** `src/daemon/lazy.test.js`, `src/executor/core.test.js`, `src/ipc.test.js`, `src/components/StatusBar.test.jsx`., `src/daemon/wire.test.js` (framing, envelope, sessions, and a scan that neither server carries its own copy), and the `runColdStartFlow` PTY check.
