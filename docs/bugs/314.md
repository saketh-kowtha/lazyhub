# Fewer key presses: remembered merge method (#314, part)

- **Area:** prs
- **Symptom:** every merge started from the same default (squash in detail and diff, merge commit in the list), so a repository that always rebases needed extra cursor moves each time.
- **Root cause:** nothing persisted the choice.
- **Fix:** the method picked in the merge picker (list, detail or diff) is remembered per repository in `[state] mergeMethods` and pre-selected next time, when the repository still allows it. Bypass and auto-merge entries are never remembered. The merge confirm is untouched (default No; admin bypass still needs the PR number typed), as #468 intended.
- **Regression test:** `src/features/prs/merge-methods.test.js`.
- **Already in place (checked):** approve, comment, labels, assignees, check out and open-in-browser run from a list row.
- **Slice 2 (this change):**
  - Smart `Enter` on a PR row (`src/features/prs/smart-enter.js`): failing CI -> failed check log, review requested of you -> Files changed, conflicts -> the Merge row of the detail, otherwise Conversation. Open PRs only. The reason is shown as a toast. "Review requested" is exact only in the `reviewing` scope because list rows carry no viewer login. `[state] smartEnter = false` turns it off.
  - The list state filter (open/closed/merged) is remembered per repository in `[state] prFilters` (`remembered-filter.js`).
  - `c` comments on the selected PR from the list (`pr.comment`); the typed text is the deliberate step, as for request changes.
  - Keystroke budgets tightened: approve 4 -> 3, failing-check log 3 -> 1; new budgets for row comment, Enter on a review-requested PR (Files) and a conflicting PR (summary). Write keys still confirm first and cancel writes nothing (`src/keystroke-budgets.e2e.test.jsx`).
  - Tests: `smart-enter.test.js`, `remembered-filter.test.jsx`, `keystroke-budgets.e2e.test.jsx`.
- **Left (Part of #314):** `Space` multi-mark with read actions (Space is the global leader key, ARCHITECT/keymap decision needed), a remembered review type (there is no review-type picker; approve and request changes are separate keys), mockup selection beyond `docs/mockups/pr-smart-enter.md`.
