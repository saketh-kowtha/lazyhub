# Config options that do nothing, a misdocumented PR scope key, and keymap self-conflicts (#465)

- **Area:** config
- **Symptom:** `[ui].density`, `[ui].show_hints`, `[ui].high_contrast`, `[diff].max_lines` and `[layout].preview_panel = false` had no effect; `[defaults].pr_scope` was documented as the PR scope but the list reads `[features.prs].default_scope`; every launch warned `[keymaps.pr-list].a maps to "pr.approve" but also matches "pr.assignees"` (also `m`, `r`).
- **Root cause:** options were parsed and never read; the docs named the wrong key; `normalizeKeyForValidation` lowercased single characters, so `a` and `A` (approve vs assignees, `m`/`M`, `r`/`R`) collided although the runtime keymap is case-sensitive.
- **Fix:** `show_hints = false` now hides the footer hints (compact footer) and `preview_panel = false` hides the PR popover. `density`, `high_contrast` and `max_lines` are removed (retired keys load with no warning; diffs are never capped, per D16; use the high-contrast theme). Docs and the generated reference name `[features.prs].default_scope`; `[defaults].pr_scope` stays as an alias while default_scope is untouched. Single-character keys stay case-sensitive in validation. `scripts/gen-legacy-defaults.mjs` rerun: no action or keymap value changed, so the table is unchanged.
- **Regression test:** `src/config/option-consumers.test.js` (shipped defaults validate with zero warnings; option consumers; scope key).
- **Sibling sweep:** the 1191-line first-launch copy was already fixed by #475 (sparse `lazyhub.toml`). Cross-lane edit: one line in `src/features/prs/list.jsx` passes `previewPanel` to the popover.
