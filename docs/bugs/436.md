# getPRChecks and getBranchProtection never reach their catch blocks (#436)

- **Area:** executor (actions)
- **Symptom:** When `gh` fails for check runs or branch protection, the call rejects instead of resolving `[]` and `null` as the surrounding code intends.
- **Root cause:** `getPRChecks` and `getBranchProtection` `return runGh(...)` inside `try` without `await`. The returned promise bypasses the `catch`, so its rejection propagates to the caller.
- **Fix:** `src/executor/actions.js`: `return await runGh(checkArgs)` in `getPRChecks` and `return await runGh(args)` in `getBranchProtection`.
- **Regression test:** `src/executor.test.js` › swallowed rejections › getBranchProtection resolves null when gh fails (its catch is meant to do that); `src/executor.test.js` › swallowed rejections › getPRChecks resolves [] when the check-runs call fails (its catch is meant to do that) (both failed before the fix).
