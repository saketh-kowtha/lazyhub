# PR label/assignee/reviewer pickers: dead while loading, silent on failure, stale selection, removal of unseen entries (#423, #513: #443 #444 #458)

- **Symptom:** after `l`/`A`/`R` no key worked until gh answered; a failing call showed an empty "No items" picker; a stale cached list showed applied labels unchecked and submit stripped them; submitting removed team review requests, assignees past the first 30 collaborators and labels past the first 100 that the picker never showed.
- **Root cause:** the loading branch rendered a bare `<Text>` with no key scope, `useGh`'s `error` was ignored, `MultiSelect` froze its selection from the first `items`, and the submit diff was computed against the PR's current values, not against what the user could see and deselect.
- **Fix:** one shared `PRSelectionDialog` (`list-dialogs.jsx`, now also used by PR detail instead of three copies) with a loading shell that handles Esc and an error shell with `FailureNotice` plus `r` retry. Current values missing from the fetched options are appended as checked rows, so the add/remove diff covers exactly what the user left checked or deselected. `MultiSelect` derives selection from `items` and keeps only the user's toggles as state, so a refreshed list re-syncs. Regression tests: `src/features/prs/list-dialogs.test.jsx`, `src/components/dialogs/MultiSelect.test.jsx`.
- **Not covered here:** the issue-side dialogs (`src/features/issues/dialogs.jsx`) get the `MultiSelect` re-sync fix (#458) but keep their own loading/failure rendering (#443/#444 siblings); `listCollaborators` pagination is unchanged.
- **Follow-up (review):** team review requests are now fetched with `slug` and `organization { login }` and identified as `org/slug` (what `gh pr edit --remove-reviewer` accepts) while the display name is shown; labels, assignees and reviewers are applied with one `editPRMembers` call (`gh pr edit --add-X ... --remove-X ...`) so a failure cannot leave half applied; `current` is snapshotted when the dialog opens so a refetch cannot move the diff base. The PTY resize flow's footer-rule check now waits for the frame instead of asserting at once (it raced on slow runners). Tests: `src/executor.test.js`, `src/flows.test.js`, `src/features/prs/list-dialogs.test.jsx`.
