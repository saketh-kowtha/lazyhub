# The diff opened from the review evidence could write, and the round trip dropped the queue record (#127)

- **Area:** prs, app
- **Symptom:** from the read-only evidence view, `d` opened the ordinary PR diff: `m`, `a`, `x`, `c`, the AI review and the conversation view (which can reply) were all reachable and the footer offered `comment`, against the #127 rule that no mutation shortcut is reachable in the review context. After the round trip the evidence view also lost the queue's evidence record, so a team review request was re-derived without it and dropped from Attention.
- **Root cause:** `PRDiff` had no review-context mode, and `app-views.jsx` passed `goToDiff` straight to `EvidenceView`, which calls it with `{number, title}`; `goToDiff` rebuilt `selectedItem` from that, so `_evidence` (and `baseRefName`) were lost and `queueRecord` changed, which re-ran the evidence read.
- **Fix:** `useDiffState({ readOnly })` (`src/features/prs/diff/state.js`, `READ_ONLY_BLOCKED`): the write, AI and comments actions are consumed with a pointer to the PR detail, the footer drops them and the header says `read-only`. `app-views.jsx` passes `readOnly={selectedItem._fromEvidence}` and opens the diff with the full `selectedItem`. The evidence view stays mounted under the diff (keep-alive stack), so row and inspected head survive; a reading that went stale while covered is read again on return, still against the inspected head.
- **Regression test:** `src/features/prs/diff/state.test.jsx` > read-only (opened from the review evidence); `src/review-queue.e2e.test.jsx` > a round trip to the diff keeps the queue record (failed before the fix), > evidence -> diff -> Esc returns to the evidence view, > a diff opened from the evidence after the reading went stale reads again; `test/pty/alpha-journey.js` (journey and boundary flows).
- **Sibling sweep:** the PR detail's own `e` evidence dialog opens the management diff on purpose (the detail is the explicit management transition); the help overlay (`?`) inside the diff is App shell and still lists the registry's diff keys, noted as remaining.
