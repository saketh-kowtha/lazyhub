# Disk cache did synchronous reads, writes and full-directory scans on the input thread (#455)

- **Symptom:** a brief frame stall after write actions and on every fetch, growing with cache size (54-67 ms with 400 x 20 KB entries).
- **Root cause:** `invalidateRepoCache` read and parsed every cache file after every write; `writeCache` did sync stringify + write + `evictCache` (readdir + stat of every file) on each `useGh` fetch; `useGh` ran a sync `readFileSync` before the memory TTL check; `prs/list.jsx` called `loadState()` (disk read) on every render.
- **Fix:** `src/cache.js` keeps a bounded in-memory mirror (filled once at startup by `warmCache()`, newest 64 files) plus an index (key -> size, mtime, repo). `writeCache` updates memory synchronously and defers stringify, atomic file write and eviction to a debounced async flush (sync flush of pending entries on process exit). `invalidateRepoCache` clears memory synchronously and removes files asynchronously using the index and a bounded readdir, reading only a 512-byte header of unindexed files (entries now start with their `meta`; legacy files are treated as unknown repo and dropped). Scans look at no more than 2000 files (the surplus is deleted); a payload over 8 MB stays memory-only and never evicts others; eviction never removes the entries just written. `useGh` seeds from memory + mirror only and reads a cold file asynchronously, in parallel with the network call, showing it as stale data if it lands first. `prs/list.jsx` reads `loadState()` once per mount. `readCache`/`listCacheEntries` stay synchronous for the CLI and daemon (not the input path); `listCacheEntries` is bounded to 2000 files.
- **Regression tests:** `src/cache.test.js` (no sync I/O on write, warm/peek, invalidate incl. foreign and legacy files, oversize payload, scan bound) and `src/hooks/useGh.test.jsx` (cold disk entry arrives asynchronously; first frame is a skeleton).
