# A key handler that threw ended the session; ErrorBoundary could only re-render the same crash (#490)

- **Symptom:** an exception in a key handler is raised from a stdin event, outside React's render, so no ErrorBoundary saw it and the process-level crash handler exited the app. The boundary's own "dismiss" re-rendered the same subtree, and its colours were hard-coded.
- **Fix:** `src/contain.js` wraps handlers: a throw or rejected promise is logged with its scope and shown as a six-second toast in the status bar. `src/hooks/useSafeInput.js` exports Ink's `useInput` through that wrapper and every app file now imports it (lint and a source scan keep it that way). `ErrorBoundary` takes colours from `useTheme()` and gains `r` to remount its subtree with fresh state; Enter/Esc still dismiss.
- **Rest (batch C):** `logSwallowed(scope, err)` in `src/contain.js` replaces every silent `catch {}` / `.catch(() => {})` on UI paths (features, components, ui, hooks, app files). It logs at debug level, collapses a repeating failure to one entry per five seconds, and with `LAZYHUB_DEBUG` set also records scope and first line into the debug-state snapshot (`swallowed`). `ErrorBoundary` takes a `section` prop that renders one quiet line instead of the full error screen; the sidebar and pane header of the main list view now each have one, so a crash there leaves the pane usable.
- **Left:** nothing in the issue's scope. `catch (err)` blocks that show the error in a toast or inline are not silent and were left alone.
- **Regression tests:** `src/contain.test.jsx`.; the pane-handler toast test, the `logSwallowed` tests, the no-silent-catch source scan and the section-boundary test are in the same file.
