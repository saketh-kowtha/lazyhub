# PR list: `M` meant both "merged filter" and "auto-merge" (#448)

- **Symptom:** the PR list header advertised `[M]merged`, but on an open PR `M` opened the auto-merge confirm.
- **Root cause:** `pr.auto-merge` and `pr.filter-merged` were both bound to `M` in the pr-list scope, and the auto-merge handler ran first.
- **Fix:** per the recorded decision, `M` is the merged filter (like `O`/`C`). Auto-merge moved into the merge picker (`m`) as "Enable auto-merge" / "Disable auto-merge" (no commit-message prompt, via `skipPrompt`) and stays in the command palette (`pr.auto-merge` now has no key). Hints and key descriptions updated; the duplicate-binding allowlist in `keymap-registry.test.js` is now empty. Regression tests: `src/config/keymap-registry.test.js`, `src/keystroke-budgets.e2e.test.jsx`.
- **Follow-up (review):** the palette entry the description promised did not exist, so `pr.auto-merge` is now a real palette action. It is a confirmed write: it disables when auto-merge is on, and otherwise enables it with the repo's preferred allowed method. List and detail share `canToggleAutoMergeFromList`. Existing users' frozen `keys = ["M"]` for `pr.auto-merge` is ignored by the #475 frozen-defaults migration, since `["M"]` is in `legacy-defaults.js`. Tests: `src/ui/actions.auto-merge.test.js`, `src/components/dialogs/OptionPicker.test.jsx`.
