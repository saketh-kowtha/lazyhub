# Large diffs were fetched, parsed and held in one shot (#509)

- **Symptom:** opening a big PR downloaded the whole `gh pr diff`, parsed it synchronously and held about three times its size in memory. Past 5,000 changed lines the pane stopped at an all-or-nothing gate, and a diff GitHub refused to return (HTTP 406) showed only "open in browser".
- **Fix:** the diff pane now loads per file. `listPRFilesPage` (GraphQL, 100 per cursor page, no patch text) gives paths and counts, so the tree and file headers render at once and the list keeps paging by cursor without refetching earlier pages. `getPRFilePatch` fetches one file's patch from the REST file list (the page its position falls on, matched by path, with a full scan only if that misses). The hook `usePRDiffFiles` loads the file under the cursor plus the next two, parses each file alone, and evicts files far from the cursor when the loaded patches pass an 8 MB budget. The existing diff skeleton is kept; the header shows "file k of N" and "listing…" while the list pages in.
- **Nothing is dropped silently:** a file that is still loading, that GitHub will not render (too large), that has no textual change (binary, mode change, rename) or that fails to load stays in the list with a note row under its header. The 5,000-line gate and the 406 screen are gone because there is no whole-diff download left. AI review still fetches the whole diff, only when it is asked for.
- **Left:** syntax highlighting is still per visible row only (unchanged); a single file with hundreds of thousands of lines is parsed whole once GitHub returns its patch.
- **Regression tests:** `src/executor/pr-files.test.js`, `src/features/prs/diff/files.test.jsx`, `src/features/prs/diff/load-order.test.jsx`, plus the diff, workflow and keystroke-budget tests moved onto `src/test/diff-fixtures.js`.
