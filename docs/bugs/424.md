# Disabling auto-merge reported success but auto-merge stayed on (#424)

- **Symptom:** `m`/`M` then "Disable auto-merge" showed "Auto-merge disabled" while GitHub still had auto-merge enabled.
- **Root cause:** `disableAutoMerge` sent `PATCH pulls/N -f auto_merge=`. The REST update endpoint has no such field, ignores it and returns 200.
- **Fix:** run `gh pr merge N --disable-auto`, then read `autoMergeRequest` back with `gh pr view` and throw "still enabled" if it is set, so callers only report success on a real change. Regression test: `src/flows.test.js` (PR auto-merge flows).
