# Browser, clipboard, editor and git spawns were copy-pasted in UI code and could not be mocked (#470, part of #479)

- **Symptom:** a fuzz run opened a real browser and ran a real `git checkout -b` because UI components spawned processes through dynamic `import('execa')` and `child_process`, which the `no-restricted-imports` rule never saw.
- **Root cause:** ten inline browser launches, four clipboard copies, four blocking editor round-trips and three git calls lived in `features/` and `components/`, each with its own platform branch. Nothing could be mocked in one place.
- **Fix:** `src/services/platform.js` (`openUrl` with an http(s)-only allow-list, `copyToClipboard` with xclip then xsel fallback, `editTextInEditor`, `runConfiguredCommand` for custom panes, re-exports of `openInEditor`) and `src/services/git.js` (`currentBranch`, `createBranch`, `pushHead`, all taking the checkout directory explicitly). Every UI call site now imports these; `cli/feedback.js` opens its URL the same way. `src/services/**` is the only new place allowed to import `execa`.
- **Left for #479:** the executor's own git helpers (`executor/branches.js`, `executor/misc.js`) still run in `process.cwd()` and should move behind `findLocalCheckout`; git writes are not yet routed through the executor classifier/audit; a global PATH-shim guard in test setup is not added.
- **Regression tests:** `src/services/services.test.js`; `src/features/issues/issues.test.jsx` (`o` and `y` go through the mockable service).
