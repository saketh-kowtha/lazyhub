# A write could leave another pane's cached read stale; PR detail waited for a round trip (#481)

- **Area:** app (data layer)
- **Symptom:** after approve, merge, close or a label edit, a view that was not the one refetching by hand kept showing the pre-write data until `r` (#439). Opening a PR showed a skeleton for a full round trip although the list already had its row (#452).
- **Root cause:** writes only dropped the disk cache (`invalidateRepoCache`); the in-memory query cache and mounted `useGh` views never heard about them, so each pane had to remember to refetch. The detail query started cold.
- **Fix:** `runGh()` announces every finished write (after the daemon cache is dropped) through `src/data/invalidation.js`. `queryClient.invalidate(prefix)` marks matching entries stale (data kept), forgets fetches that began before the write so their pre-write result is never stored, and tells mounted queries to revalidate in the background (no loading frame; views on one key share one fetch). `useGh` keys are now `[host, account, repo, fn, ...deps]` so a repository invalidates by prefix. The PR list seeds the detail key with the row (`partial`, timestamp 0), so the detail renders on the first frame; keys that need the full PR wait until it lands. The memory cap in the docs now says 64 MB, as the code does.
- **Regression test:** `src/data/invalidation.test.jsx` (mounted views update without `r`; other repos untouched; seed never overwrites a fuller entry), `src/executor/core.test.js` (write announced after the daemon invalidation, failed writes too, reads never), `src/features/prs/detail-seed.test.jsx` (first frame from the row, requests issued together, partial PR gates actions), `src/data/no-sync-fs.test.js` (no sync fs in `hooks/` or `data/`).
- **Sibling sweep:** the disk cache already writes asynchronously with an in-memory index (#455); `loadState()` is read once per PR-list mount. Explicit `refetch()`/`refreshPR` calls in panes are kept for now (the list patches single rows with `refreshPR`); removing them and per-mutation `invalidates` declarations are the remaining R3 work.
