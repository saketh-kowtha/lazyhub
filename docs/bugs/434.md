# useGh: stale response overwrites newer data and clears loading (#434)

- **Area:** app (hooks)
- **Symptom:** after switching repo/filter/scope quickly, the list showed the previous query's rows and the spinner vanished while the new request was still in flight.
- **Root cause:** `useGh` guarded async results only with `mountedRef`; the effect cleanup set it false and the next run set it true again, so an older in-flight promise passed the check and called `setData`/`setError`/`setLoading(false)`. Last-resolved won, not last-requested.
- **Fix:** per-request generation (`reqRef`). Every `fetchData` takes a new id, cleanup bumps it, and only the current id may set state or write the cache. `useGh`'s API is unchanged.
- **Regression test:** `src/hooks/useGh.test.jsx` › "a slow response for the previous deps must not overwrite the newer deps", "an old response landing while the new request is in flight must not clear loading" (failed before the fix).
- **Sibling sweep:** all `useGh` call sites share the hook, so they are fixed together.
