# Number keys 1-9 no longer switch panes (#398)

- **Area:** app
- **Symptom:** pressing `1`, `2`, `3`... in the real app did nothing; only `Tab` and `g` chords moved between panes.
- **Root cause:** #340 (part of #312) deleted the `parseInt(input)` pane-jump handler in `src/app.jsx` and a registry test banned any digit binding, reserving digits for PR-detail sections (#201) that never shipped. Nothing else consumes digits.
- **Fix:** new rebindable registry action `app.jump-pane` (keys `1`-`9`, in `schema.js`, `defaultConfig.toml`, help overlay via `GLOBAL_KEYS`); the global handler in `app.jsx` calls `goToPane(PANES[n-1])` in list and detail views, after the dialog/input/overlay scope guard and the help check. Indices follow `active_panes`, so `focus` is 1 and custom tabs are included.
- **Regression test:** `src/app.e2e.test.jsx` › `number keys jump to the Nth active pane from the list and from detail` (failed before the fix); also `number keys do nothing while a pane dialog (search, pickers) is open` and `number keys do nothing while the help overlay is open`.
- **Sibling sweep:** search/filter in prs, issues, branches, notifications and actions open a dialog that calls `notifyDialog`, so digits are blocked; PR-detail search and issue reply claim the `input` scope; diff/comments/conflict views keep their own keys. Tab/custom panes have no text input.
