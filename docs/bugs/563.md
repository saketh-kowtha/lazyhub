# The `@` author filter was a blind free-text box (#563)

- **Symptom:** `@` in the PR list asked for an exact login with no suggestions; a typo only showed up as an error after the search ran.
- **Root cause:** `AuthorSearchDialog` was a bare `TextInput`; no data we already hold (row authors, collaborators, earlier filters) fed it.
- **Fix:** the dialog is now a searchable list (`src/features/prs/list-dialogs.jsx`, helpers in `src/features/prs/author-candidates.js`). It merges the loaded PR rows' authors, `listCollaborators` (already paged; "showing first N" when capped) and recent filters kept per repository in `[state].recentAuthors`. Typing filters fuzzily and case-insensitively; Enter on a suggestion applies it, and a "Use ... as typed" row means free text that matches nothing is still applied as-is. While collaborators load a loading row shows and Esc works; on failure the cause shows and the text field keeps working. Names are passed through `sanitize()`. Hints come from the existing `dialog.*` registry entries. The issues pane has no author filter, so there is no second call site.
- **Regression test:** `src/features/prs/list-dialogs.test.jsx` "author filter list (#563)" and `src/features/prs/author-candidates.test.js`.
