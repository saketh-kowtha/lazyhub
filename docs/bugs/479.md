# UI code and tests could still reach git and the OS without one seam (#479, R1)

- **Symptom:** after #470 moved the browser, clipboard and editor launches behind `src/services/`, the git helpers in `src/executor/branches.js` and `src/executor/misc.js` still ran in `process.cwd()` with no check that it was a clone of the viewed repo (the conflict view and the New PR form), git writes bypassed the executor's classifier and audit, `src/editor.js` was a spawn site outside the allowed directories, and nothing stopped a test from starting the real `open`, `git` or `pbcopy`.
- **Fix:**
  - `src/executor/git.js` is `runGit()`, the git counterpart of `runGh()`: the argv is classified by `classifyGit` (in `src/daemon/protocol.js` next to `classifyGh`; reads and known writes only, any global option before the subcommand is refused), a write writes an `intent` and a `result` audit entry and is blocked when the audit log is unavailable, and the directory is required (no default to `process.cwd()`).
  - `src/services/git.js` is the whole local-git API, every function taking the checkout directory: `currentBranch`, `checkout`, `createBranch`, `push`, `unpushedCommits`, the conflict helpers (`isInMerge`, `conflictedFiles`, `countConflictMarkers`, `stage`, `unstage`, `mergeAbort`, `commit`, `mergeBranch`, `mergeMessage`) and `findLocalCheckout`/`remoteMatchesRepo` (moved from the executor). The marker count and the merge message are read from files instead of spawning `grep` and `cat`.
  - The branches pane, the conflict view and the New PR form resolve the clone with `findLocalCheckout(repo)` and pass its directory. Without a clone the conflict view shows "No local checkout of <repo> here; run lazyhub inside a clone to use local git actions" and runs no git; the New PR form skips the local branch hint and unpushed check and refuses the push with the same message. Pushes go to the remote that points at the viewed repo.
  - The editor launcher moved to `src/services/editor.js`; `src/editor.js` re-exports it, so imports and test mocks of that path are unchanged.
  - `src/test/setup-hermetic.js` puts shims for `open`, `xdg-open`, `git`, `pbcopy` and `xclip` at the front of PATH in every test worker. A shim records its call and exits 97, and the file's `afterAll` fails the run if any was called. Tests that need the genuine git (throwaway repos) read it from `LAZYHUB_REAL_GIT`.
- **Threat model:** local git writes now have the same audit and fail-closed behaviour as gh writes (T7, unobserved paths). Residual risk: local operations are audited by intent and outcome, not content.
- **Tests (batch C):** `src/services/git.test.js` (classifier, runGit audit and blocking, timeouts, conflict helpers, and a scan that no file outside `services/`, `executor/`, `bootstrap.js`, `daemon/`, `ai/providers/` imports `execa` or `child_process`, and that git is only started in `runGit`), `src/services/git.checkout.test.js` (moved), `src/features/prs/ConflictView.nocheckout.test.jsx`, updated `ConflictView.*`, `NewPRDialog` and branches pane tests; the PATH guard was seen failing a probe test that ran `open`.
- **Left:** nothing from the issue. #470 and #471 were already closed.
