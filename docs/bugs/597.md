# #597: whole view reloads on every action (lane V3a: Ink full-terminal clear)

Verified in `node_modules/ink/build/ink.js` (Ink 4.4.1): when the rendered output is at least as tall as
`stdout.rows`, Ink writes `ansiEscapes.clearTerminal + fullStaticOutput + output` instead of its normal
in-place log update. The Shell root was `<Box height={rows}>` with `rows` equal to the terminal rows, so
every frame cleared and repainted the whole terminal.

Fix: `computeLayout` (src/hooks/useLayout.js) is the single source of `rows` for every full-height root
(Shell, TooSmall, overlays, help, palette, AI, repo picker, queue). It now reports `rows = terminalRows - 1`
and keeps the real size as `termRows` (used for the "now WxH" line of the too-small message and for the
too-small / sidebar / compact-footer thresholds). The first-run onboarding root already reserved a row.

Gate: `test/pty/clear.js` (run from `npm run test:pty`) drives 50 keys in an 80x24 PTY (navigation, detail,
back, help, refresh) and asserts zero ESC[2J / ESC[3J after first paint. Before the fix: 136 clear
sequences; after: 0. Resizes are excluded (none are sent).

Cost of one frame is unchanged (Ink rewrites the whole region): about 2.5 KB per keypress before (2509 B)
and after (2365 B). The visible effect is that the terminal is no longer cleared, which removes the flash.
