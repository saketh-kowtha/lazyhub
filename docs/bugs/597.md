# Views reload on almost every action; there was no way to measure it (#597, lane V0)

- **Area:** app (perf instrumentation)
- **Symptom:** "For almost every action entire views are kind of reloading." No tool could say how often, or prove a fix.
- **Root cause:** nothing observed frames, clears, remounts or warm-path gh calls, so the suspects (Ink full-screen clear when output height >= rows, whole-tree swaps for overlays and list/detail, loading states during revalidation, repo-wide invalidation) were unverified.
- **Fix (V0 only, measurement; no behaviour change):**
  - `src/perf/vitals.js`: opt-in recorder (`LAZYHUB_VITALS=1`, JSONL to `LAZYHUB_VITALS_FILE` or the OS temp dir, mode 0600, never the repo, no network). Disabled it is one shared no-op (no fs, timers or listeners). Events carry only whitelisted fields; frames keep a byte count and a clear flag, never text. `src/app.jsx` passes the stdout given to Ink through `vitals.wrapStdout()` (identity when disabled): Ink 4.4.1 has no onRender hook, so the stdout write is the only place a frame is observable.
  - `src/perf/vitals-metrics.js`: pure metric math (bands, p95, CLEAR, FLASH, REMOUNT, WARM-GH).
  - `test/perf/vitals.js` + `vitals-lib.js` (`npm run vitals`): 80x24 PTY against the `perf` fake gh at 300 ms/call, screen states from the existing `TerminalScreen` emulator in `test/pty/fixtures.js` (so no new dependency), fake-gh call log, recorder JSONL.
  - `src/perf/vitals.mount.test.jsx`: in-process REMOUNT for overlay close and list -> detail -> back.
- **Regression test:** `src/perf/vitals.test.js` (disabled path: zero fs calls/timers/listeners; privacy: no fixture strings in the file), `src/perf/vitals-metrics.test.js`, `src/perf/vitals.mount.test.jsx` (baselines on main: the base list remounts; `it.fails` targets flip when V3 lands).
- **Baseline on main (80x24, 300 ms/call, one run; `npm run vitals`):** FMF-cold ~450-490 ms, FMF-warm ~17-35 ms, KTF-nav p95 17-32 ms, KTF-open ~6 ms, FRAME-BYTES ~1.5x grid. Failing: CLEAR 86-88 of 88-90 frames carry ESC[2J/ESC[3J (Ink clearTerminal, confirms risk 1); WARM-GH:reopen 1 call (a PR-detail graphql for the selected row when the list is re-opened); REMOUNT 1 extra mount of the base list for both an overlay open+close and list -> detail -> back. Measured OK on main: FLASH 0 and WARM-GH 0 for help/palette close, back-nav, re-entry and manual refresh (the 30 s query cache covers them), so the "reloading" feel on main is dominated by CLEAR and remounts, not by skeleton flashes or gh traffic in these flows.
- **Sibling sweep:** harness drives the PR list, issue list, help, palette, detail; AI and repo-picker overlays, SHIFT, ROW-RENDER, ACT-GH and OPT-FB need hooks from later lanes and are not measured yet.
